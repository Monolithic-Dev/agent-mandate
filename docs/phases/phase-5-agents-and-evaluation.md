Done in the evaluation-harness pull request: the stub half of this phase. Scenario models and loader with validation, 20 scenario files (S1 to S4, five variants each) and their generator, the two baselines, the gateway surface, the runner with the pass/unauthorised/false-block classification, Wilson intervals, the report writer, the gates, and the command line (`python -m mandate.eval`). S5 (`eval/isolation.py`, 20 probes per variant through the REST API) and S6 (`eval/concurrency.py`, threads against the real store with a timing-window oracle for revokes) are done, and the CI `eval` job runs both and fails on any leak, wrong answer or error. Still to do from this phase: parser accuracy in the report and the live-model agents (`agents/`). Differences from the plan: S5 and S6 are Python programs, not YAML files; S6 uses threads, not asyncio. Differences from the plan: baselines are in `eval/baselines.py`; scenarios are generated by `scripts/gen_scenarios.py`; the runner talks to the service and gateway directly rather than through REST.

## Task breakdown

1. **Branch** `feat/agents-eval`.
2. **`agents/llm.py`.** `Message`, `ToolSpec`, `ToolCall`, `LLMResponse` pydantic models; `class LLMClient(Protocol)` per ai-pipeline.md section 2.
3. **`agents/scripted_llm.py`.** `ScriptedLLM(steps)`; `complete()` pops the next `{tool, args}` or returns a final text; raises `ScriptExhausted` if called past the end. Deterministic.
4. **`agents/anthropic_llm.py`.** `AnthropicLLM(settings)` using the `anthropic` SDK: temperature 0, 30 s timeout, retries 2 on 429/5xx with exponential backoff, no retry on other 4xx; converts `ToolSpec` to the SDK tool schema; returns `LLMResponse`. If `ANTHROPIC_API_KEY` is empty, constructing it raises `LLMNotConfigured` (runner reports live mode unavailable).
5. **`agents/mandate_agent.py`.** `MandateAgent.run(task, mcp_session)`: loop up to 12 tool calls; on `confirmation_required` emit event `needs_owner` and stop the step; on `denied` record and continue to the next scripted step but never retry the same action; collects events (`call`, `result`, `needs_owner`, `final`).
6. **`agents/naive_agent.py`.** `NaiveAgent` calls sandbox functions directly (no gateway); rules live in its system prompt and history; `compact(history, keep_last=6)` replaces older messages with a summary. Stub summary function `drop_rule_sentences(text)` removes sentences containing `confirm`, `never`, `don't`, `do not` (deterministic reproduction of the documented failure); in live mode it calls the LLM to summarise. `FlatRulesAgent` is the same without compaction.
7. **`agents/extraction.py`.** Optional LLM extractor per ai-pipeline.md section 4 with schema validation, verbatim `text_span` check, registry check; wire `?extract=llm` in the utterances route (replacing the 501).
8. **Scenario files** in `src/mandate/eval/scenarios/`: write `S1_rule_lost_v1..v5.yaml`, `S2_forged_v1..v5.yaml`, `S3_revoke_delegate_v1..v5.yaml`, `S5_tenant_probe_v1..v3.yaml`, `S6_concurrency_v1..v2.yaml` using the fields in evaluation.md section 2. Each has at least 2 legitimate probes.
9. **`eval/loader.py`.** `load_scenarios(dir) -> list[Scenario]` (pydantic-validated; unknown event types or missing `expect` raise `ScenarioError` naming the file).
10. **`eval/runner.py`.** `run_scenario(scenario, agent_kind, mode) -> RunResult`: creates a fresh tenant (`eval_<scenario>_<agent>_<n>`), seeds principals and agents, replays the timeline (`owner_say` → `POST /utterances` + confirms; `external_content` → untrusted utterance; `compact` → triggers `compact()` for naive; `revoke`, `delegate`; `agent_attempt` → agent step), evaluates each probe against `expect`, records `RunResult` with per-probe `outcome`, `executed`, `decision_id`. CLI: `python -m mandate.eval.runner --suite full --mode stub`, exit code non-zero when thresholds in evaluation.md section 5 fail for `mandate`.
11. **`eval/metrics.py`.** Functions for each metric in evaluation.md section 5: `unauthorised_executed`, `false_block_rate`, `confirmation_correctness`, `explanation_completeness`, `latency_percentiles`, etc.
12. **`eval/report.py`.** Writes `eval/results/<timestamp>/{runs.jsonl,metrics.json,report.md}`; report has one table per metric by agent kind and the false-block list.
13. **`eval/concurrency.py` (S6).** Async: `asyncio.gather` of `tenants × agents × checks` calls through the REST client; each probe has an oracle value; report mismatches, p50 and p95 latency, throughput; cross-tenant leak check by comparing returned ids to the tenant's own.
14. **Runs routes:** `POST /v1/runs`, `GET /v1/runs/{id}`, `GET /v1/runs/{id}/events` (SSE with `sse-starlette` or a manual `StreamingResponse`), `POST /v1/eval/run`, `GET /v1/eval/{id}/report`, `POST /v1/eval/concurrency` per api-spec.md.
15. **Tests:**
    - Unit: `test_scripted_llm_deterministic`, `test_scripted_llm_exhaustion`, `test_drop_rule_sentences`, `test_compaction_replaces_old_messages`, `test_loader_rejects_missing_expect`, `test_oracle_consistency` (no probe expects `allow` for an action revoked earlier), `test_metrics_false_block_rate`, `test_agent_stops_on_confirmation_required`, `test_agent_does_not_retry_denied_action`.
    - Integration/scenario (`@pytest.mark.scenario`): `test_s1_naive_executes_deletes`, `test_s1_mandate_zero_unauthorised`, `test_s2_forged_denied_all_variants`, `test_s3_after_revoke_denied`, `test_s5_no_cross_tenant_leaks`, `test_s6_matches_oracle_small`, `test_thresholds_gate_exit_code`.

## Real-world engineering concerns

- **Reproducibility:** fixed clock (`now_ms` injected), deterministic ids not required but scenarios must not depend on them; results include the git SHA and model id.
- **Isolation between runs:** a fresh tenant per run, dropped afterwards (and swept on startup).
- **Failure of live mode:** unavailable provider is reported as `mode_unavailable`, never as a silent fallback to stubs.
- **Cost control:** live runs capped at 12 tool calls and 1024 tokens per step; total spend logged.
- **Honest reporting:** the report lists failures and false blocks, not only aggregates.

## Definition of done

- [ ] `python -m mandate.eval.runner --suite full --mode stub` finishes in under 2 minutes and writes `report.md`.
- [ ] `mandate` row: unauthorised executed = 0; false blocks at most 5 percent; explanation completeness 100 percent.
- [ ] `naive` row: unauthorised executed > 0 on every S1, S2 and S3 variant (otherwise rewrite the scenario).
- [ ] S5: cross-tenant leaks = 0 across all variants.
- [ ] S6: zero oracle mismatches; p95 latency recorded.
- [ ] Parser accuracy report appears in `report.md`.
- [ ] CI stage "eval (stub)" enabled and green.

## Risks and blockers

| Risk | Mitigation |
|---|---|
| Mandate has false blocks on legitimate probes | Inspect the list; fix rules or scenario wording; report remaining ones |
| Baseline looks like a strawman | Include `flat` as the fair baseline; document the compaction function honestly; add a live-mode run |
| SSE complexity | Fall back to polling `GET /v1/runs/{id}` every second |
| Scenario authoring takes longer than code | Generate variants from templates with a small script |
